# Themes, bar and desktop appearance

## Palette source

~/.config/dwm-titus/themes.toml selects [active].theme and defines palettes plus [appearance] values. ~/.local/bin/theme-apply.sh resolves to the deployed scripts/theme-apply.sh; maintain the repository counterpart too. Generated outputs include Polybar colors.ini, Rofi active-colors.rasi, terminal active-theme files, GTK CSS/settings, Qt colors, dunst, btop, Papirus overlay, the starship palette block, editor theme, browser flags/policies and theme-env.sh. Customize the generator or source palette for durable changes.

[theme.dynamic] is a generated section: theme-set-dynamic (matugen + matugen-dynamic-map) rewrites only that block from a wallpaper and requires matugen/PIL; never hand-edit it. Wallpaper picker/carousel/random must call wallpaper-apply, which applies the picture (feh writes ~/.fehbg, replayed by autostart) before staging or applying palette generation. Palette failure must not undo wallpaper selection. Three pickers exist — rofi grid (wallpaper-picker.sh, SUPER+CTRL+W), carousel (SUPER+W) and caelestia (wallpaper-caelestia) — plus wallpaper-random.sh on SUPER+SHIFT+W; only the wallpaper-apply path regenerates a dynamic palette. The Control Center's own randomize action bypasses it.

Theme apply has a lock and broad side effects: it regenerates several apps, restarts Polybar/tray processes, may close/restart Thunar and repaints existing dwm borders by cycling focus (dwm paints borders on focus/manage only; new windows are always correct). Use it for palette changes, not routine bar sizing. theme-audit reports drift per layer without writing. Editor-extension and browser-policy mechanics are in [editors-browsers.md](editors-browsers.md).

## Polybar

Active config is selected by the live launch.sh; on this laptop it is themes/minimal/laptop-config.ini. Main and secondary bars have different module lists. Treat right-divider as static layout decoration. Preserve module actions, indicators and event subscriptions for styling edits.

    polybar-msg cmd restart

The main bar's 27px content plus 1px bottom border yields 28px total; verify the actual X window geometry. Font indices in %{Tn} are one-based, font-n definitions zero-based.

Fontconfig's default DPI can differ from Polybar's. This system explicitly matches font patterns and bar DPI at 96. Scalable fonts resolve through points and native integer pixel sizes; a requested 0.5px increment can round into a larger visible step. Do not claim fractional rendering without checking.

Current routes in fonts.ini: base text fonts 0/1 and workspace font 14 use 14px; headphone font 5 uses 15px; keyboard font 16 uses 17px; active workspace font 17 uses 14px; bell/WARP/sun/plug font 18 uses 14px; power font 15 uses 13px; slim-divider font 19 uses 12px. These compensate different glyph shapes, not different desired visual weights. Recheck the file when editing.

dwm-tags.sh listens to root X properties; first five slots remain visible and higher tags appear when used. The label-padding/margin keys support side-specific values; the attempted format-padding-left styling was ineffective here. Check actual spacing, clipping and click hit areas. Compare screenshots at equivalent scale; video thumbnails are not native-DPI references.

Wi-Fi tray arcs are generated by papirus-folder-color in Papirus-Dynamic, with the active foreground passed by theme-apply.sh. Preserve signal levels, folder links and app/brand inheritance. Tray artwork has its own pixel size, independent of font size.

## OSK and other appearance

Polybar's osk-toggle.sh generates the Onboard theme/layout, centers a floating force-to-top overlay and applies the native X11 border. SUPER+F9 toggles it; SUPER+Q closes it first when running. Its X button must quit, not hide a resident process. The drag strip is a native move action. Closed means no Onboard process.

Terminal, Rofi, GTK/Qt, dunst and icon configuration roots are conventional ~/.config locations. Qt uses qt6ct/qt5ct when installed (theme-apply sets only color_scheme_path, or clears it for light mode); otherwise QT_QPA_PLATFORMTHEME falls back to gtk3. Picom must be verified before adding blur/transparency; configuration alone does not start a compositor. Cursor size is exported from ~/.xprofile and mirrored to X resources; toolkit-only settings are not equivalent.

The starship prompt palette is generated in place inside ~/.config/starship.toml between the two `starship theme palette` marker comments; the layout above them is user-owned. Editing the palette by hand is overwritten on the next apply — expose a new token in the generated block instead. Starship re-reads the file per prompt, so no restart is needed.

xsettingsd receives the GTK theme/icon names and a HUP so X11/XFCE apps follow; nwg-look is the GUI editor for GTK settings. Both are downstream of theme-apply, not alternative palette sources.

Login appearance is LightDM-related: inspect the active greeter in /etc/lightdm/ and the repository lightdm/ files. Bootloader styling is a separate host task; do not replace boot configuration to change a desktop palette.

VS Code-family editors get a generated local extension (`DWM Jabir`); browser content scheme and frame use separate flag and managed-policy paths. Both have side effects and JSONC/enterprise-policy caveats — read [editors-browsers.md](editors-browsers.md) before touching them.
